### 1. `CAPSEC_COVERAGE_REGRESSION` (RED) 신설 — 축은 **소스 내 존재 여부**

직전 배포본(main) diff 비교는 **보조**로만 두고, 1차 판정은 git 없이 되는 축으로 잡을 것:

| 상태 | 판정 |
|---|---|
| 사이드카가 선언한 per-bond 소스에 **회사 자체가 없다** | **RED** (= raw 부재, 검증 불가) |
| 소스에 회사가 **있고** 채권 전부 `outstanding_mn == 0` | 정당한 0 (전액상환) — 통과 |
| 소스에 회사가 있고 잔액>0 인데 마스터가 0 | **RED** (어댑터/필터 버그) |

핵심은 **"소스에 없음"과 "소스에 있고 0"을 구분**하는 것이다. 지금은 둘 다 `no_bonds_in_dart`
한 값으로 뭉개져서 구분이 불가능하다 — 이 구분이 안 되면 룰이 성립하지 않으니, 필요하면
`bond_coverage`에 값을 하나 더 늘리는 것(`absent_in_source` 류)까지 이 발주 범위로 본다.
단 `kics_forward_capital.json`은 배포 에셋이니 **기존 값·필드는 지우지 말고 추가만**.

기대 모집단은 하드코딩하지 말고 **회사별 self-census**(`feedback_no_category_assumptions`):
무발행사(9사)는 정당한 0이고, `capital_securities_fy2025.json`에 레코드가 있는 회사가 기준.

### 1. `CAPSEC_COVERAGE_REGRESSION` (RED) 신설 — ✅ 배선

`scripts/validate_data_contract.py` `check_census` **1e** (`_capsec_coverage_findings`).
판정축은 요청대로 **선언된 per-bond 소스 안의 회사 존재 여부**이고, git diff는 쓰지 않는다.

| 상태 | 판정 | 라이브 결과 |
|---|---|---|
| 소스에 회사 레코드 없음 | **RED** | 15사 발화 (KR0050·KR0076 포함) |
| 소스에 있고 해당 슬라이스 잔액 0 | 통과 | KR0069 삼성생명 (유일한 `bonds: []` 실례) |
| 소스에 잔액>0 인데 마스터 0 | **RED** | 라이브 0건 (24사 전부 소스와 정확 일치) |

**라벨은 믿지 않는다** — `20260803T0056Z`의 교훈대로 게이트는 마스터의 `bond_coverage` 값을 읽지 않고
사이드카가 선언한 소스 파일을 **직접 읽어** 존재 여부를 도출한다(`index_bond_source`, DART/FSC 2계보
스키마 모두 처리). 모집단도 하드코딩 없음 — **마스터가 실제로 행을 발행한 회사**가 검사 대상(self-census).

부수 가드 2개:
- **`CAPSEC_SOURCE_UNRESOLVED`(RED)** — 마스터가 행을 발행하는데 사이드카에 소스 선언이 없으면
  커버리지 검사가 **빈 껍데기**가 된다(2c가 겪은 실패 유형). 축 소실 = 통과 아님.
- **`CAPSEC_AMOUNT_MISMATCH`(YELLOW)** — 0은 아니지만 소스와 금액이 `max(1억,1%)` 넘게 어긋나는
  부분 유실. 라이브 실측 0건이라 관찰기 YELLOW, 1~2 릴리스 후 RED 승격 예정.

오탐 억제: 슬라이스별 자기검열(신종만 발행한 회사의 후순위 0은 대상 아님) + tier 마스터는 소진율
분자(신규분)가 아니라 **경과조치 면제분까지 더한 총액**을 존재 신호로 사용(전액 pre-2023인 회사가
정당한 0으로 오탐되는 것 방지).

**`bond_coverage` 3-way 확장도 했다**(요청 범위 내, 배포 에셋 **추가만**):
`dart_listed`(레코드+발행) / `no_bonds_in_dart`(레코드+무발행) / **`absent_in_source`**(레코드 없음).
`scripts/forward_capital_simulation.py::_bond_coverage`. 재생성 diff = `bond_coverage` 15행 +
KR0069 confidence 사유 1건뿐, **수치 무변**(38행 그대로).
> 같이 발견해 고친 것: `compute_confidence`의 no-bond 지름길 리터럴이 `no_bonds_in_fsc`로 남아
> **rename 이후 죽어 있었다**. 복구하되 `absent_in_source`에는 적용하지 않는다 — 스캔도 안 한 회사에
> "reconcile 할 게 없으니 high"는 이 티켓이 지적하는 바로 그 낙관 주장이다.
