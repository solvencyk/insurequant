### 1. "표 자체가 부정합" — 아니다. 뺄셈 자리에 덧셈을 했다

회신은 *"자산+부채 합산 1,635,761,446 ≠ 기초 잔액 (1,977,369,986)"* 을 근거로 원천 이상을 의심했다.
그 표의 정의는 **잔액 = 부채 − 자산**(자산은 음의 부채)이다. 그렇게 계산하면 **7개 열 전부 정확히** 맞는다:

| 열 | 기초 부채 − 기초 자산 | = 기초 잔액 |
|---|---|---|
| PV | (170,804,270) − 1,806,565,716 | **(1,977,369,986)** ✓ |
| RA | 34,102,606 − (187,379,280) | **221,481,886** ✓ |
| CSM 공정가치법 | 10,011,593 − (80,648,614) | **90,660,207** ✓ |
| CSM 수정소급법 | 362,152,751 − (1,161,800,476) | **1,523,953,227** ✓ |
| CSM 전환이후 | 106,582,411 − (487,051,473) | **593,633,884** ✓ |
| 취득현금흐름 | (7,584,857) − 342,248,171 | **(349,833,028)** ✓ |
| 합계 | 334,460,234 − 231,934,044 | **102,526,190** ✓ |

기말 행도 같은 방식으로 7/7 정확히 일치한다. **이 표는 흠이 없다.**

### 2. 내 iter 1 진단 정정 — "스케줄 표에서 뽑았다"도 틀렸다

값은 진짜 측정요소별 변동표에서 나온 게 맞다. 스케줄 표 합계가 CSM 잔액과 같은 건 **정상**이다 —
그 표는 *"보고기간말 현재 CSM 을 기대상각기간별로 배분"* 한 것이라 합계가 곧 기말 잔액이다.
두 표가 같은 값을 내는 건 오류가 아니라 **교차확인**이다. 내가 "할인 전 단순합이라 더 크다"고 쓴 건 오독이다.

같은 이유로 **"항목4 는 plug" 도 취소**한다. 실제로 raw 에서 그대로 나온다:

```
추정치 변동분 (19,834,758)+(288,761,573)+(109,697,251) = (418,293,582) = -4,182.9억
계약의 경계 변경 효과 1,040,413,242+1,723,301,727+675,686,637 = 3,439,401,606 = +34,394.0억
합계 = +30,211.1억  == 마스터 항목4
```

FY2023 필링의 롤포워드는 **정확히 닫힌다**(22,082.5 +7,221.6 +816.6 +30,211.1 −5,176.2 = 55,155.5).

### 3. 진짜 원인 — 회사가 FY2023 을 소급재작성했다

같은 FY2023 인데 두 필링이 다른 숫자를 말한다. **양쪽 다 자체적으로는 완벽히 닫힌다**(둘 다 재계산 확인):

| FY2023 CSM | 원공시 (감사보고서 2023.12, `20240409003674`) | 재작성 (감사보고서 2024.12, `20250409002702` 의 **전기 비교표시**) |
|---|---|---|
| 기초 | 22,082.5억 | **35,264.0억** |
| 기말 | **55,155.5억** | **32,301.6억** |

결정적 차이 한 줄: 원공시에는 `기타 → 계약의 경계 변경 효과` 가 있고 CSM 에 **+34,394억**을 얹는다
(순부채 영향은 0 = 측정요소 간 재배분). **재작성본에는 그 줄이 아예 없다.**
회사가 FY2023 의 계약경계 변경 처리를 뒤집은 것이다.

- **정정공시는 없다.** 라이나생명은 비상장이라 감사보고서만 내고, DART 목록 4건 전부 확인했다
  (2023.12 / 2024.12 / 2025.12 ×2). 재작성은 **다음 해 보고서의 전기 비교표시로만** 반영됐다.
- 그래서 우리 마스터가 2023.4Q=원공시, 2024.4Q=재작성본 기준을 나란히 들고 있어 경계가 깨진 것이다.
  **어느 쪽도 파싱 오류가 아니다.**
