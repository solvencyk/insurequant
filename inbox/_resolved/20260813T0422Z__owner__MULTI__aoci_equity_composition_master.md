### 3. 마스터 스펙

파일: 루트 `equity_composition.json`. 스키마는 기존 마스터 9키 그대로
(`원보험사코드 / 원수사명 / 티커 / 생손보여부 / 항목번호 / 항목명 / 공시분기 / 값 / 값_당분기`).

**단위 = 백만원** (FS API는 원 단위 → `/1e6`, `fetch_dart_fs.py`와 동일).
**기준(basis)** = OFS(별도) 기본, `fetch_dart_fs.py:BASIS_CFS`(KR0069 삼성생명, KR0001 메리츠)만 CFS.
PL과 기준이 갈리면 브리지가 깨지므로 **반드시 같은 규칙을 재사용**할 것(상수 복붙 말고 import).
corp_code는 런타임 이름검색(`resolve_corp`) — **영구 매핑 파일 신설 금지**(기존 룰).

항목번호:


- **28 기타(잔차)** 는 29 − (21..27 합) 으로 *역산*한다. 회사별로 OCI 세부행 명칭이 갈리는데
  잔차로 흡수해야 항등식이 닫힌다. 잔차가 |29|의 20%를 넘으면 세부행 매핑 누락 의심 → 진단 로그.
- **6과 30은 서로 다른 소스**(BS vs SCE)에서 각각 채운다. 같게 만들려고 한쪽을 복사하지 말 것 —
  **둘의 일치가 검증 항등식**이다(§4).

**값 vs 값_당분기 (여기서 조용히 깨지기 쉬움):**
- 스톡 항목(1-19, 20, 30): 스톡에는 누계 개념이 없다 → `값 == 값_당분기`.
- 플로우 항목(21-29): FS API SCE의 중간기는 **누계**다 → `값` = 누계,
  `값_당분기` = 당기누계 − 직전분기누계. 1Q는 `값_당분기 == 값`.

**부호**: 적립(환입)예정액은 환입 시 음수, AOCI는 상시 음수 가능. 원부호 보존, 절대값화 금지.

### 4. 자체 검증 항등식 (파서가 빌드 중 자체 체크 — validation에도 별도 발주함)

1. `20 + 29 == 30` (AOCI 롤포워드 폐쇄)
2. `30 == 6` (SCE 기말 == BS 스톡) — **이게 어긋나면 기준(OFS/CFS) 오선택 의심**
3. `29 == 21+22+23+24+25+26+27+28` (28은 잔차이므로 정의상 성립 — 잔차 크기만 감시)
4. `1 == 2+3+4+5+6+7` (자본총계 폐쇄, 있는 항목만)
5. 직전분기 `30` == 당분기 `20` (연속성). **FY 경계 포함.** 깨지면 RED — "소급재작성"으로 면제 금지.
6. `5 >= 10+12+14` (법정준비금은 이익잉여금 내 적립) — 위반 시 항목 오매핑 의심.
