## 미결 (sender 작성)

`data/dart/_fs_api_cache` 의 삼성생명 CFS 캐시 2개에서 **재무상태표 자산·부채 총계가 1Q 값에
붙박여** 있다. 신규 마스터 `equity_composition.json` 의 항등식 검사(자산 = 부채 + 자본)가 잡았다.

```
파일                              자산총계        부채총계        자본총계        40 = 41+1 ?
00126256_2025_11013_CFS.json  318,858,553  287,368,034  31,490,519   ✓ 정확히 닫힘
00126256_2025_11012_CFS.json  318,858,553  287,368,034  33,657,838   ✗ 잔차 -2,167,319
00126256_2025_11014_CFS.json  318,858,553  287,368,034  40,923,920   ✗ 잔차 -9,433,401
00126256_2025_11011_CFS.json  350,685,701  285,850,383  64,835,318   ✓
00126256_2026_11013_CFS.json  371,424,249  288,123,252  83,300,997   ✓
```

(단위 백만원. `ifrs-full_Assets` / `ifrs-full_Liabilities` / `ifrs-full_Equity`, sj_div=BS, thstrm.)

**왜 파일 통째 stale 이 아닌가**: 같은 파일 안에서 **자본총계는 분기마다 정상적으로 갱신**된다
(31.5조 → 33.7조 → 40.9조). 응답을 통째로 재사용했다면 자본도 같이 멈췄어야 한다. 즉 파일이
잘못 저장된 게 아니라 **그 응답 안에서 BS 자산·부채 행만 이전 분기 값**이다.

### 요청

1. 위 2개(11012 = 반기, 11014 = 3분기) **재페치 후 같은 값이 다시 오는지** 확인만 해달라.
   - 값이 바뀌면 → 캐시 교체(당시 API 응답 문제). 파서에 raw_ready 통지.
   - 그대로면 → **DART 원천 결함**으로 확정. 그 판정 문장을 답변에 남겨주면 validation 이
     documented exception 으로 등재한다(근거 링크가 이 답변이 된다).
2. 판정이 나오기 전까지 이 2셀은 RED 로 남긴다. "아직 안 받아봤다"는 예외 사유가 아니라는
   기존 규칙 그대로다.

> 범위 밖 참고: 삼성생명은 CFS 기준사(`fetch_dart_fs.BASIS_CFS`)라 OFS 는 대상이 아니다.
> 다른 회사·분기에는 같은 패턴이 없다(Tier-1 243 (회사,분기) 전수 대조에서 이 2건만 발화).

(단위 백만원.) 4개 reprt 전부 응답 status=000(정상), 013 아님 — DART가 "데이터 없음"이 아니라
**틀린 데이터를 일관되게** 돌려주고 있다. 11012/11014 두 셀 다 자산·부채가 11013(1Q)과 소수점까지
완전히 동일한 값으로 재확인됐고, 같은 응답 안의 자본총계는 분기마다 정상 갱신됨(요청 원문의 관찰과
일치) — 즉 캐시 문제가 아니라 **DART API가 반기보고서(11012)·3분기보고서(11014) 조회 시 재무상태표
자산·부채 태그만 1분기(11013) 값을 반환**하는 소스 결함. 자본변동표 계열 태그는 별도 XBRL 블록이라
영향을 안 받는 것으로 보인다(확정 아닌 추정 — DART 측 원인 규명은 스코프 밖).

**영향 범위 확인**: `fetch_dart_fs.py`의 Tier-1 추출(`_parse`)은 IS/CIS(손익계산서) 항목만 뽑고
BS는 안 읽는다 — 기존 PL_breakdown 마스터는 이 결함과 무관. 이번 신규 `equity_composition`의
BS 항등식 체크에서만 발화한 문제로 한정된다.

**결론**: 캐시 교체 불필요(이미 최신 라이브 값과 동일), raw_ready 통지 없음(값이 안 바뀌었으므로).
validation은 이 답변을 근거로 (KR0069, 2025.2Q)·(KR0069, 2025.3Q)의 자산/부채 두 셀을
documented exception(DART 원천 결함, EQ_BS_IDENTITY)으로 등재 가능. 재정정공시가 뜨면
`--refresh`로 재확인 가능(코드에 이미 있음, 상시 모니터링 대상은 아님).
