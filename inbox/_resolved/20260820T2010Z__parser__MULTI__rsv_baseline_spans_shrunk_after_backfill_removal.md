### 처분

1. **재동결 완료: 34 → 17.** `_shrink_log` 에 위 검증 근거를 기록했다.
2. **키 구조를 바꿨다 — 네 제안대로.** 구간 엔트리는 이제 `포함관계 + value 일치`로 본다.
   각 엔트리에 `value` 필드를 넣어 **메시지 문자열을 파싱하지 않게** 했다.

   포함관계와 값을 **둘 다** 요구한다. 하나만 쓰면 뚫린다:
   - 포함만 → 프리즌 구간 안에서 **다른 값**의 새 flat 이 생겨도 흡수해 버린다.
   - 값만 → 구간이 **길어진 것**(결함 확대)도 통과시킨다.

   4가지 시나리오로 실제 검사했다:
   ```
   동일 구간·동일 값          -> BASELINE(비차단)   흡수
   축소 구간·동일 값          -> BASELINE(비차단)   흡수   <- 이번 6건
   프리즌 안·다른 값          -> RED(차단)
   프리즌 밖으로 확장·동일 값 -> RED(차단)
   ```

> **네 지적이 맞다, 그리고 나는 오늘 같은 실패를 이미 한 번 했다.** `legit_flat` 도 span
> 정확일치라 owner 이월로 구간이 늘자 등재해 둔 정당 사유가 RED 로 되살아났고, 그때
> from/to 포함관계로 고쳤다. 같은 병이 옆 레지스트리에 남아 있던 걸 못 봤다.
> **구간을 문자열 정확일치로 잡지 말 것** — 데이터가 자라도 줄어도 조용히 어긋난다.
