### R-RSV-11 `RESERVE_ROLLFORWARD_IDENTITY` — **RED** (owner 지정 신규, 2026-08-19 추가)

> **전기말 기적립액 + 전기 적립예정액 == 당회기 기적립액**

`기적립액`은 회계연도 내내 상수(주총 처분 전 잔액)이므로 **검사 지점은 FY 경계**다:

```
기적립액(FY n+1) == 기적립액(FY n, 4Q) + 적립(환입)예정액(FY n, 4Q)
```

환입 국면이면 예정액이 음수로 들어와 그대로 성립한다. 예외가 없는 회계 항등식이므로 **RED**.

**오케스트레이터 실측(FS API 캐시 전수, 4개 항목 × 전 회사 × FY 경계 89건):**

### 추가 (validation, 2026-08-19T0910Z) — **R-RSV-2 / R-RSV-3 명세에 구멍이 있다**

파서 회신으로 확인된 사실이라 owner 확인이 필요하다.

두 룰은 **"괄호·△ = 음수"를 무조건 전제**한다(근거 셀 서술: *"표 프레이밍(조정이익·이익잉여금
차감 표기)을 그대로 읽어 부호가 뒤집힌 것"*). 그런데 **반대 방향 함정이 같은 빈도로 존재**한다.

실측(NH농협손해보험 2026.2Q, 단위 백만원):

```
비상위험준비금 반영전 반기순이익   71,666
비상위험준비금 적립 예정금액      (6,004)
비상위험준비금 반영후 조정이익    65,662     <- 71,666 - 6,004
```

여기서 괄호는 **"이익에서 차감"**이고 준비금은 그만큼 **증가**했다. 적립액 = 303,485 + 6,004
= **309,489**다. 나는 잔액표 관례를 그대로 적용해 297,481로 보고했고, 파서가 이를 반박해 정정했다.

**정정 제안 — 부호 해석은 표 종류로 갈린다:**

| 표 종류 | 지문 | 괄호/△ |
|---|---|---|
| 조정이익 프레임 | `반영전 순이익` · `반영후 조정이익` · `주당 조정이익` | **반전** (차감 = 준비금 증가) |
| 잔액표 · BS 계정 | `기적립액` · `적립(환입)예정액` · `잔액` | 그대로 **음수** |
