### P-1. **BS 기준을 전사 OFS(별도)로 고정하라 — 삼성생명 RED 2건의 진짜 원인** (최우선)

`build_ifrs17_bs.py` / `build_equity_composition.py` 가 `fetch_dart_fs.BASIS_CFS = {KR0069, KR0001}`
를 그대로 물려받아 **삼성생명·메리츠 BS를 연결(CFS)로** 뽑고 있다. 그 규칙은 **PL 헤드라인 gold 답지가
연결이라서** 만든 것이고, BS에는 근거가 없다.

**전수 측정 (`data/dart/_fs_api_cache` 937파일):**

| 기준 | BS 항등식(자산 = 부채+자본) 검사대상 | 위반 |
|---|---|---|
| **OFS** | 254건 | **0건** |
| CFS | 85건 | **2건 — 전부 삼성생명(00126256) 2025.2Q/3Q** |

삼성생명 CFS 응답은 **자산총계·부채총계가 2025.1Q/2Q/3Q 세 분기 완전히 동일**하다
(자산 318,858,553 / 부채 287,368,034 백만원 — DART 연결 응답 자체의 stale). OFS는 정상이다:

| 분기 | CFS 자산 | OFS 자산 | OFS 부채 | OFS 자본 | OFS 차이 |
|---|---|---|---|---|---|
| 2025.1Q | 318,858,553 | 281,011,504 | 257,067,089 | 23,944,415 | **0** |
| 2025.2Q | 318,858,553 (동일) | 280,990,354 | 255,077,729 | 25,912,625 | **0** |
| 2025.3Q | 318,858,553 (동일) | 295,578,120 | 262,873,644 | 32,704,476 | **0** |

→ **파서가 "DART 원본 캐시 품질 이슈, 우리쪽 수정 대상 아님"으로 종결한 그 건은 오판이다.**
DART 원본이 깨진 게 맞지만 **깨진 건 CFS 쪽이고, 우리가 그 쪽을 선택했다.** OFS로 바꾸면 소멸한다.
`IFRS17_BS.json` 에도 이 stale 값이 그대로 실려 있다(현재 삼성생명 2025.1~3Q 자산총계 3분기 동일).

**할 일**
1. **BS 계열 빌더는 전사 OFS 고정.** `BASIS_CFS` 참조를 BS 경로에서 제거한다.
   PL(`fetch_dart_fs.py` 본체)은 **건드리지 말 것** — gold 답지가 연결이라 그건 그대로 맞다.
   두 빌더가 같은 상수를 import 하고 있으니, 상수를 지우지 말고 **BS 쪽에서 무시**하는 형태로.
2. 메리츠는 OFS/CFS 둘 다 항등식이 닫혀서 지금 티가 안 났을 뿐, 같이 OFS로 간다(별도가 정본).
3. 부수 소멸: **항목 8(비지배지분)은 연결에서만 나오는 행**이다. OFS 고정이면 필요 없어진다.
   행을 지우진 말고, 자본총계 폐쇄식에서 8을 기대하지 않게 되면 된다.

### P-2. **AOCI 결측 13건은 "AOCI가 0"이 아니라 회사가 태그를 갈아탄 것 — item7에 잘못 들어가 있다**

owner 가 "한화생명 2023.3Q는 실제로 AOCI가 0 아니었냐"고 물었다. **아니다.** 그 분기 OFS BS 자본
섹션 전체는 이렇다(백만원):

```
자본금                  ifrs-full_IssuedCapital                       4,342,650
기타불입자본             ifrs-full_AdditionalPaidinCapital              -637,717
신종자본증권             dart_HybridBonds                                498,344
이익잉여금               ifrs-full_RetainedEarnings                    6,238,955
기타자본구성요소          dart_ElementsOfOtherStockholdersEquity        2,085,384   <-- 이게 AOCI 자리
자본총계                ifrs-full_Equity                             12,527,616
```

합이 자본총계와 **원 단위까지 정확히 일치**한다. AOCI 행이 0이 아니라, **행 이름이
"기타포괄손익누계액"이 아니라 "기타자본구성요소"이고 account_id 가 `dart_` 확장태그**일 뿐이다.

**결정적 증거 — 같은 회사가 태그만 갈아탔다:**

| 한화생명 OFS | account_id | 라벨 | 값(백만) |
|---|---|---|---|
| 2025.1Q | `dart_ElementsOfOtherStockholdersEquity` | 기타자본구성요소 | -2,241,833 |
| 2025.2Q | `ifrs-full_AccumulatedOtherComprehensiveIncome` | **기타자본구성요소(라벨 동일)** | -2,152,928 |
| 2026.1Q | `ifrs-full_AccumulatedOtherComprehensiveIncome` | 기타포괄손익누계액 | -705,811 |

라벨이 그대로인 채 태그만 바뀌었고 값도 연속이다(-2,241,833 → -2,152,928). 흥국생명은 더 심해서
**분기마다 왔다 갔다** 한다(2023.3Q `dart_` / 2023.4Q·2024.4Q `ifrs-full_` / 2025.1Q~2026.1Q 다시 `dart_`).
값은 연속이고(-421,112 → -715,511 → -614,352 → -629,741), 폐쇄식도 닫힌다
(흥국생명 2025.1Q: 80,120 + 298,227 + 49,650 + 953,966 + (-715,511) = 666,452 ≈ 자본총계 666,451).

**현재 우리 마스터의 실제 상태 = 오분류다.** `BS_ACCT[7]`(자본조정)에
`dart_ElementsOfOtherStockholdersEquity` 가 들어 있어서, **한화생명 2.08조가 "자본조정" 칸에 실려 있다**
(item6 은 빈칸). 결측이 아니라 **잘못된 칸에 표시 중**이고, 화면에 나가면 그대로 틀린다.

**전수 측정 — 이 패턴은 딱 2사 13분기다** (OFS 캐시 254건 중 BS는 있는데 AOCI 태그 없음):

```
한화생명(00113058)  2023.3Q, 2023.4Q, 2024.1Q, 2024.2Q, 2024.3Q, 2024.4Q, 2025.1Q   (7)
흥국생명(00167068)  2023.3Q, 2025.1Q, 2025.2Q, 2025.3Q, 2025.4Q, 2026.1Q            (6)
```

**할 일**
1. item6 매핑에 `dart_ElementsOfOtherStockholdersEquity` 를 **조건부**로 추가한다.
   **무조건 추가 금지** — 다른 회사에선 진짜 자본조정일 수 있다. 채택 조건:
   같은 (회사,분기) BS 에 `ifrs-full_AccumulatedOtherComprehensiveIncome` **가 없을 때만** item6 으로 채택.
   있으면 지금처럼 item7 유지.
2. **채택 전 검산 필수:** 자본총계 폐쇄식(1 = 2+3+4+5+6+7)이 닫히는지 셀마다 확인하고,
   안 닫히는 (회사,분기)가 나오면 채택하지 말고 답신에 목록으로 올려라.
3. `dart_ElementsOfOtherStockholdersEquity` 와 `dart_CapitalAdjustments` 가 **동시에** 있는 회사가
   몇 사인지 전수로 세어서 답신에 적어라(흥국생명 2023.3Q는 자본조정=0 으로 둘 다 있다).
   이 축을 재보지 않고 룰을 넣으면 다른 회사를 망친다.
4. **SCE(자본변동표)로 가지 말 것.** BS 안에서 끝난다.
