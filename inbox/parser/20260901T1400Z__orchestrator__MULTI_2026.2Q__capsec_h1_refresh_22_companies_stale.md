### 1-1. 요청 #3 — hybrid_confirm_partial 2건이 왜 발행실적 표에 안 나오나 (사모/창밖 가설 검증)

**가설이 맞았다, 실측 확인.** `scripts/_probes/capsec_company_detail.py KR0001` 로 FY2025
기준선을 직접 대조:

- KR0001 메리츠화재 제2회(발행 2022-04-07)·제3회(발행 2022-06-30) — 둘 다 이름에 **"(사모)"**
  라벨이 붙어 있고, 발행일이 2022년(현재 2026-06-30 기준 4년 전)이다. `_issuance_as_of`
  로 확인한 KR0001의 발행실적표 창은 2026-06-30 근처 최근 발행분만 담는데(도크스트링:
  "이 표는 잔액 전량이 아니라 보고창 안의 발행실적"), 2022년 사모 발행분은 그 창 밖이라
  안 뜨는 게 정상이다 — 파싱 누락이 아니다.
- KR0082 DB생명 제2회 신종자본증권은 **이미 잔액 0**(2025-03-31 조기상환 완료, FY2025
  시점에 이미 소멸)이라 애초에 "미상환 발행실적"에 뜰 이유가 없다 — 창 문제조차 아니고
  개념적으로 대상이 아니었다. §2의 "잔액 0 채권 확인 제외" 로 해결.

두 경우 다 **발행실적표의 구조적 한계**(보고창 제한, 미상환만 등재)이지 회사쪽 공시
누락이 아니다. KR0001 제2·3회는 이번 수정으로 **채권별 확인은 여전히 실패**(발행실적에
없으니 당연)하지만, tier 전체가 그 실패에 묶이지 않고 **집계-불변(BS 신종자본증권
총액) 경로로 구제**된다(아래 §2의 3번 항목 참조) — 값은 그대로, 시점만 2026-06-30 으로
정직하게 이동.

### 2. 고친 것 — `scripts/build_capital_securities_fy2026h1.py`

1. **`confirm_bonds_still_outstanding` 을 전량-게이트에서 채권별 부분확인으로 재설계.**
   기존엔 tier 안 채권 하나라도 못 찾으면 tier 전체가 FY2025 에 묶였다(동양생명 실측:
   후순위 3건 중 2건 깨끗이 매치되는데 미국달러 후순위채 1건의 환산액면 드리프트 때문에
   3건 다 막힘). 이제 채권 단위로 시점을 올리고, 매칭은 **발행일 우선**(우리 목록에서
   그 발행일이 유일하면 액면 불일치를 눈감음 — 외화채 대응), 여럿이면 액면까지 맞춘다.
2. **이미 잔액 0인 채권은 확인 대상에서 제외**하고 시점만 정직하게 올린다(신한라이프
   KR0094 신종자본증권 1건, DB생명 KR0082 신종 1건, 동양생명 KR0087 신종 1건 — 전부
   FY2025 이전에 이미 전액 상환된 레거시 채권이 tier 전체를 인질로 잡고 있었다).
3. **레이어드 폴백 버그를 발견·직접 수정** — 채권별 확인을 먼저 만들었더니 메리츠(KR0001)
   가 회귀했다(3건 중 1건만 채권별로 확인되고, 예전엔 셋 다 구제하던 집계-불변 폴백이
   "뭔가 확인됐다"는 이유로 통째로 스킵됨). `confirm_tier_asof` 헬퍼로 통합해 **1차가
   놓친 채권에는 항상 2차(집계-불변)를 마저 시도**하도록 고쳤다. 회귀는 이 세션 안에서
   잡아 최종 산출물엔 반영 안 됨(전후 대조로 확인).
4. **`detect_redeemed` 를 상환+동시신규발행 케이스로 확장**(요청 #3과 무관, §3 참조).

**무결성**: 39사 전체 `total_hybrid/subordinated_outstanding_mn` 전후 대조 — 델타 있는
회사 **1개**(KR0005, 의도한 변경, 아래). 나머지 38사는 금액 델타 0(`source_file`/`as_of`
만 이동). 재현: `python scripts/_probes/capsec_diff_totals.py <before.json> <after.json>`.

### 3. 새로 잡은 상환 — 흥국화재(KR0005) 제20회 상환 + 제23회 신규발행

`redeem_candidate_unreconciled` 로 막혀 있던 케이스(부분집합 탐색이 "뺄셈만" 해서, 상환과
신규발행이 같은 반기에 겹치면 영원히 실패). raw 원문에서 **이사회결의 2026-02-06 "1.
후순위사채 조기상환 및 신규 발행의 건"** 을 찾았고, 발행실적표에서 제23회(2026-03-31,
액면 100,000백만) 를 확인했다. `detect_redeemed` 에 "1차(순수상환) 실패 시 신규발행 후보
하나를 더해 재시험" 을 추가 — **제20회(45,000백만, 콜 2026-03-05 경과) 상환 + 제23회
(100,000백만) 신규를 유일해로 재현**(BS 당반기말 319,060 vs 265,000-45,000+100,000=320,000,
0.3% 이내). 신규발행 후보 탐색은 **absent 채권이 있을 때만** 2차로 돈다 — 처음엔 이 가드가
없어서 교보(KR0073)·KDB생명(KR0072) 처럼 상환이랑 무관한 회사에 노이즈성
`redeem_candidate_unreconciled` 를 냈다가, 원인을 잡아 즉시 되돌렸다(absent=[] 인 회사는
이 경로에 들어오지 않게).

### 4. 못 뚫은 것 — KR0068 한화생명 (다음 세션 인계용 정밀 진단)

**표는 찾았다** — `차입금에 대한 세부 정보 공시` 열그룹, 15개 물리컬럼 중 정확히 4개가

금액행 라벨 = `차입금(사채 포함)`, 값은 **장부가**(399,222 vs FY2025 399,167 — 상각 드리프트
+55, 확인됨). 남은 결정 사항 둘:
  - 표 제목이 문서에 **2회** 등장(위치 ~11.1M, ~18.1M) — 연결/별도 구분인지 확인 필요.
    잘못 짚으면 컬럼 인덱스가 밀려 엉뚱한 금액을 후순위채에 붙일 위험.
