### 1) 원인 — 가설이 아니라 두 개의 확정된 기전

`_prefer_ofs` 는 정상이다. 깨지는 곳은 그 앞단인 `_tag_basis`/`_ofs_line_boundary` 다.

**(가) 경계 탐지가 `ENG=` 속성에만 의존한다.** `_OFS_TITLE_RE` 가 `<TITLE ATOC="Y" ENG="...">`


문단 `"4-1. 재무상태표"`(L54,609)가 같은 자리를 가리킨다.

**(나) lxml `sourceline` 이 65,535 에서 포화한다.** 추출기가 쓰는 `etree.HTMLParser` 는

### 추가 — 악사손해 RED 을 파서로 닫을 수 있는지 끝까지 봤다 (결론: 못 닫는다)

발주만 하고 넘기지 않고, 별도 감사보고서 첨부만으로 PL Tier-2 를 뽑을 수 있는지 실측했다.

**뽑기는 뽑힌다.** `_00760.xml` 안에 손보 Format-B(장기/자동차/일반) 노트가 있고,
`extract_tier2_sonbo_structured` 가 item4 = 22,272,512천원 = **222.7억** 을 낸다 —
CSM 워터폴 상각 222.7억과 정확히 같다.

**그런데 파이프라인이 그 값을 버리고 있었고, 그 이유도 결함이다.**
`parse_filing` 마지막 줄이 `if code not in SONBO_HANDLERS: t2 = _reconcile_tier2_unit(t1, t2)` 인데,
이 조건은 **틀린 질문**이다. 악사(KR0049)는 `SONBO_HANDLERS` 에 등록돼 있지만 그 핸들러
(`extract_tier2_axa`)는 연차 '보험손익 상세내역' 노트 전용이라 이 필링에서는 `{}` 를 낸다.
그러면 아래 Format-B 폴백이 **천원 단위**로 값을 채우는데, 등록만 돼 있다는 이유로 단위 보정이
건너뛰어져 1000배인 채 남고, RC 게이트가 ΣLOB ≫ 보험손익 을 보고 items 2-14 를 통째 억제한다.
바로 위 주석이 *"corrects 천원/원 LOB notes (e.g. 악사 Format-A)"* 라고 **악사를 예로 들고 있는데**
정작 악사가 그 보정에서 빠져 있었다.

조건을 "핸들러가 실제로 값을 냈는가"로 바꿔 보면 `_reconciled: True` 가 되고 item4 = 222.7억으로
RED 이 닫힌다. **그런데 같이 딸려오는 값이 못 쓸 것이라 배선하지 않고 되돌렸다**:

```
item6(원수 예실차)  = -487,465백만 = -4,875억   <- 보험수익 8,537억의 57%. 불가능
item7(기타)        = +469,293백만              <- item6 의 잔차 거울
item11/item12 도 같은 방식으로 +1,192 / -1,158억 로 상쇄
```

**RED 하나를 지우려고 화면에 못 쓸 숫자를 싣는 것은 이 저장소가 두 달 싸운 false-green 그 자체라
하지 않았다.** 그래서 결론은 그대로다 — 본문 XML 이 와야 제대로 닫힌다(발주 완료).

다만 **단위 보정 가드 결함은 악사 하나의 문제가 아니다**: `SONBO_HANDLERS` 에 등록된 11개사 중
어느 필링에서든 핸들러가 비면 같은 일이 난다. 고치려면 그 11개사 전 분기 census 가 먼저라
이 커밋에서 분리했다. 재현: `scripts/_probes/probe_20260826_axa_parsefiling.py`.
