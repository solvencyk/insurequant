## 4. 안전 규칙 (이번 작업 한정 추가)

1. **기존 39개사의 셀을 한 칸도 바꾸지 않는다.** 마스터(`kics_disclosure.json` 등) 반영 전 백업을 만들고, 반영 후 `코드 ∉ KR1101-1107` 행의 전후 diff = 0 임을 기계로 확인한다. fill 스크립트가 md_inbox 전체를 다시 upsert 하는 부작용이 있으므로 입력은 재보사 MD 만 담은 임시 디렉터리로 격리한다(환경변수 `SOLVENCY_MD_INBOX_DIR` 등, 스크립트가 허용하는 방식으로).
2. **마스터 JSON 쓰기는 한 번에 한 에이전트만**(동시 쓰기는 조용한 유실). 병렬은 raw 수집·docling MD 변환·경영지표 스테이징까지만이다.
3. **봇 차단·확인창(Cloudflare 등)·로그인은 우회하지 않는다.** 직접 PDF 주소(검색 결과·표준 curl `--ssl-no-revoke -m 30`)로 받아지는 것만 받고, 막히면 `blocked` 로 적어 owner 에게 올린다. 가짜 User-Agent 로 위장하거나 확인창을 푸는 시도 금지.
4. 받은 파일은 **열어서** 지점명·기수·기준일을 확인한다. 존재와 올바른 분기 원문은 다르다. 키워드 0회 ≠ 원문 없음(스캔본 가능성부터).
5. "틀린 값을 싣느니 빈 칸." 문서 안에서 쪽마다 값이 어긋나면 임의 선택하지 말고 둘 다 기록하고 비운다. 추측·보간 금지. 음수는 데이터 부호 그대로(화면 △), 단위 백만원↔억원 주의.
6. `git push` 금지, 커밋은 오케스트레이터. `scripts/`·`src/` 수정은 parser 레인이 새 양식을 읽기 위해 꼭 필요할 때만, 기존 회사 산출이 바뀌지 않음을 골든 테스트(`tests/test_kics_rules_golden.py` 등)로 확인한 뒤.
7. 회사코드(KR번호)는 사내 전용 — 주소·화면에 쓰지 않는다.
8. 게이트 계약: `validate_kics_disclosure.py` RED=0 이거나 documented exception. **exception 등재는 owner 만** — 재보사 RED 중 발행사 자기모순이면 "등재 제안"으로 보고서에만 쓴다.

## 5. stage 별 할 일

- **downloader(회사별)**: registry 의 list_page·직접 주소 패턴으로 2026.2Q→2023.1Q 의 분기 공시 + 보조 문서 수집, 열어서 검증, 매니페스트. 사이트에 안 올라온 분기는 `not_posted` 로 근거(목록 스냅샷)와 함께 기록.
- **parser-kics(회사별 MD) → parser-kics(단일 로더)**: (a) 회사별로 `run_harness.py --stage parse` 를 **`--companies` 로 자기 코드만** 돌려 MD 생성(기존 회사 MD 덮어쓰기 금지), MD 품질 확인, 회사 특유 양식(손해/생명장기 구성, 경과조치, 간이공시 분기) 메모, 경영지표 요약 스테이징 추출. (b) 단일 로더가 fill_period → fill_subitems → fill_market → IRR 순으로 최신 분기부터 반영하고 게이트를 돌려 RED 를 줄인다.
- **validation**: 기계 검산만(육안 판정 제외). 기대 그리드(회사 × 매니페스트 상 존재 분기 × 항목) census, 적용전·후 양쪽 전 룰, 문서 표지 요약표의 지급여력비율·금액과 마스터 값 대조(fitz 로 독립 재독), 경영지표 항등식(자산=부채+자본, 보험손익+투자손익=영업이익), 기존 회사 셀 diff = 0. 결함은 inbox 로 담당 stage 에 발주.

## 7. owner 결정 (2026-10-09, 이 절이 앞선 프롬프트·메모보다 우선한다)

1. **상충 규칙**: 같은 (회사, 분기, 항목)이 여러 공시에서 실제로 다르면 무조건 가장 최근 공시의 전기·전년동기·직전분기 칸 값을 채택한다(당기 칸 정본 아님). 덮어쓰기 전 값은 runlog 에 남긴다. 에이전트가 "전기 칸 오기로 보인다"고 판단하지 않는다.
2. **반올림 차이는 상충이 아니다**: 두 값이 같은 숫자의 서로 다른 반올림 표기일 뿐이면(소수 자릿수가 다르고 거친 쪽 값이 정밀한 쪽 값의 반올림과 같음. 예: 1331.23 대 1331, 209.1733 대 209.17, 34.2 대 34) 상충으로 보지 않고 **더 정밀한 값(소수 자릿수가 많은 쪽)을 채택**한다. 최신 공시 쪽이 더 정밀하면 그 값, 기존 값이 더 정밀하면 기존 값을 둔다. 패치 목록의 `hold`(반올림형) 행과 "정수로 덮는" 행은 이 규칙으로 정리한다.
3. **0 인쇄는 덮지 않는다**: 최신 공시의 전기 칸이 0(예: RGA 2024.4Q·2025.4Q 순자산 0 인쇄, 구성항목 합이 지급여력금액과 같아 인쇄 오류로 보임)을 인쇄했을 때 기존 비영(非零) 값을 0 으로 덮지 않는다. 기존 값을 채택하고 runlog 에 사유를 적는다.

5. 마이브라운의 DART 공시 확인은 DART 점검이 끝난 뒤로 미룬다(지금은 경영공시 PDF 만 사용).
